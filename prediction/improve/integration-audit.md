The prompted join validates the original game/model/opponent mapping and rejects duplicate input keys, including ambiguous representations. It checks group, family, representation, and payoffs when supplied by the original forecast row. The original forecast format has group and representation metadata but no payoff vector. Probabilities must be finite and structurally supported; null predictions remain null. Completed probabilities require a timezone-aware source timestamp. Rows carrying observed successes, opportunities, rates, or target labels are rejected. Missing primary query/target pairs and valid prediction counts are recorded in the output manifest. The original source bytes and output bytes are hashed.

Collection first rechecks the prepared design and forecast evidence. It requires a terminal runner state, either `complete` or `finished_with_errors`; a running source cannot produce a supposedly final collection. The latter terminal state may legitimately contain missing episodes. Each trace must have the exact scheduled episode ID and path, pass the unchanged original trace verifier, and produce exactly two distinct planned focal roles with matching game, group, family, model/opponent, trial, display swap, representation, and payoff metadata. Copied traces, reused successful calls, unplanned complete episode directories, and changes during verification are rejected.

The original trace verifier checks prompts, canonical actions, payoff calculations, raw call responses, and model configuration. The added collector checks exact round/role decision filenames and stores hashes of the decisions and raw calls as well as the traces. All recorded call timestamps—including failed calls, unused attempts, and retries—must follow the forecast freeze. Selected calls must not postdate their completed trace. Resumed traces may start after their cached calls; those cached calls must still follow the forecast freeze. Timestamps must include timezones.

The collector preserves the complete planned query order: all 448 real-cohort contexts remain in the exported data. A wholly missing context receives `successes=null`, `opportunities=0`, `value=null`, and a false observation mask; absence is never converted into observed noncooperation or an observed zero rate. Partly observed contexts pool actual integer counts only. Self-play retains both focal rows from each episode. Scope indices are checked against both the original training IDs and fresh query IDs before constructing the full and family-excluded scoring folds.

The audit reports observed and missing contexts, distinct episode/role counts, complete and partial canonical groups, actual label-orientation counts, selected successful and all recorded call counts, and the original runner's reported coverage/errors.
