# Numerical prediction entry points

Run from `/shared/allie/strategy-behavior` with `/shared/allie/venvs/hole/bin/python -B`. No modeling command makes API calls. Dependencies are isolated in `prediction/vendor`: scikit-learn 1.8.0, SciPy 1.17.1, joblib and threadpoolctl. The existing environment was not upgraded.

The prespecified design is [modeling-protocol.json](modeling-protocol.json). It was written before access to empirical rollout labels. Baselines are marginal, ordered model/opponent context (`pair`) and family means; a memoryless Nash comparator; raw/derived/combined ridge and count-weighted logistic regression; a 16-unit MLP with/without both identities; and focal/opponent/both identity ablations for combined logistic regression. The `pair` baseline preserves focal roles: A playing B and B playing A have separate means. The MLP with identities permits nonlinear game–model–opponent interactions. Structural features exclude literal raw/normalized payoff coordinates and raw magnitude statistics. Logistic fitting uses success/failure pseudo-observations, with total weight one per canonical game; no rounding or synthetic Bernoulli draws are used.

```bash
/shared/allie/venvs/hole/bin/python -B -m prediction.modeling evaluate \
  --input prediction/runs/RUN/measurements.jsonl \
  --outdir prediction/runs/RUN/numerical \
  --splits family,random_group,interpolation,extrapolation,pair,model \
  --bootstrap 300
```

`evaluate` deliberately reads held-out labels and should run only when evaluation is authorized. It writes `specification.json`, actual `run_config.json`, `folds.json` (indices, group memberships, exclusions), `fit_audit.json` (training support, selected parameters, warnings and vocabularies), `predictions.jsonl`, `scores.json` and the structural-family comparison plot. Root-level `scores` and `fold_scores` arrays contain `rate_mae`, `rate_rmse`, `event_brier`, `event_log_loss`, `calibration_ece`, weighted Pearson/Spearman correlations and support. `comparisons_to_marginal` and `comparisons_to_pair` report paired improvements. The ordered-context comparison tests whether game structure adds signal beyond model/opponent differences. Uncertainty resamples game groups and complete episodes, preserving both focal players; it conditions on the fitted forecasts and does not refit training sets.

Family, random and parameter splits purge canonical game groups. Pair/model splits reuse game structures deliberately to isolate the held-out identity axis. Model holdout removes every training row where the held-out model occurs in either role. Parameter splits use `split_metadata.canonical_t`: train outer/test middle tercile for interpolation; train lower+middle/test upper for extrapolation. Undefined coordinate groups are excluded from both partitions and logged. `--parameter canonical_s` is available as an explicitly selected secondary analysis. Representation transfer uses matrix training and a held-out nonmatrix representation; no folds are emitted when only matrix rows exist.

Fit on training-only rows and freeze forecasts before prospective rollouts:

```bash
/shared/allie/venvs/hole/bin/python -B -m prediction.modeling fit \
  --input prediction/runs/RUN/training-measurements.jsonl \
  --artifact prediction/runs/RUN/fitted.pkl
/shared/allie/venvs/hole/bin/python -B -m prediction.modeling forecast \
  --artifact prediction/runs/RUN/fitted.pkl \
  --input prediction/runs/RUN/prospective-feature-rows.jsonl \
  --output prediction/runs/RUN/prospective-forecasts.jsonl
```

Forecast inputs contain `game_id`, `group_id`, `family`, `payoffs`, `features`, `model`, `opponent`, and optional episode/trial/representation metadata. `targets` may be absent. A forecast manifest records creation time and artifact/input/forecast SHA-256 hashes; the fitted artifact has a companion JSON audit. Fit and forecast refuse to overwrite either the requested output or its companion JSON/manifest; use a new path for a new freeze. Numerical artifacts are Python pickles generated by this package, intended for the same recorded dependency environment.

`--targets action0,first_action0` and `--methods marginal,pair,family,nash,combined_logistic,combined_logistic_both` select an explicitly recorded subset. Omitting these options runs all seven contract targets and fifteen methods, except Nash conditional-target forecasts, which are intentionally unavailable. `--no-tune` fixes regularization at one; otherwise ridge/logistic parameters are selected within up to three training-game-group folds. MLP settings are fixed. The inner folds never use outer test features for scaling or identity encoding. An unseen identity activates no fitted identity coefficient; unseen ordered model/opponent contexts and families fall back to the training population mean. The exported `pair` row field and pair-holdout grouping remain unordered so both directions are withheld together.

Rate scoring averages eligible rows within each game and then averages games. Binomial Brier/log loss use counts to weight events within each game, then average games. They are different metrics: Brier includes irreducible Bernoulli variation whereas rate MSE does not. Every comparison uses the intersection of supported held-out rows across participating methods; support losses and missingness are exported. No opportunity is interpreted as an observed zero rate. The Nash baseline predicts only universal actions and unconditional cooperation/coordination under a fixed symmetric equilibrium selection; it does not invent responses to impossible conditioning histories.

Synthetic validation:

```bash
/shared/allie/venvs/hole/bin/python -B -m unittest prediction.test_modeling -v
```

Tests cover held-out-family signal recovery, complete episode/game grouping, unseen-model purging, train-only feature scaling, raw/derived ablation separation, null eligibility, affine-safe parameter splits, event-count scoring, game-equal weighting, block uncertainty, Nash selection, a finite MLP, common scoring support and forecast deserialization in a fresh process with no test labels.
